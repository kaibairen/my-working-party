## 2. 信息架构（决策人默认 `/`）

```
┌─────────────────────────────────────────────────────────┐
│ AI 办公室                          待办 · n（开抽屉）   │
├──────────────────┬──────────────────────────────────────┤
│ 目标             │ 工位心跳（Roster · 只读）             │
│ · 列表（人读名） │ · 头像/名/在忙|等证据|空闲            │
│ · [新建目标]     │ · 禁止拖拽派工、禁止开跑前置          │
│ · 每条下：填充槽 │                                      │
│   （Bot 填/人填）│                                      │
└──────────────────┴──────────────────────────────────────┘
         │ 待办 · n 或卡片角标
         ▼
┌─────────────────────────────────────────────────────────┐
│ 抽屉：待我拍板（唯一硬 HITL · G1 文案锁）                 │
│ 通过 / 打回重做 / 稍后处理 · 还差人话 · 工程详情折叠     │
└─────────────────────────────────────────────────────────┘
```

| 区域 | 决策人要看见 | 禁止 |
|------|--------------|------|
| 目标列表 | Goal 人读标题、状态一句 | UUID 作标题、OpenAPI |
| 新建目标 | 短表单：名称 + 一句话要什么 | Brief 禁键/步骤剧本 |
| Bot 填充板 | 槽位：谁在填、填到哪、产物入口；空槽「我来填」（`human_allowed` 或 exception_grant） | 把填充板当派工台；步骤脚本 |
| 工位心跳 | Bot 自报心跳（`display_name`）；按组折叠；空态「还没有 Bot 报心跳」 | 把执行池当同事、拖拽指派、dispatch 按钮 |
| 待我拍板抽屉 | G1 卡面（已通过的 #8 口径） | 再升回唯一首页 |

## 3. 主路径 5 步（点点）

1. 进办公室 → 看见目标列表（可空）+ 工位心跳  
2. **新建目标**（或点已有目标）  
3. 在目标下看 **Bot 填充槽**（自动/协调者填；人可读进度，不派工）  
4. 工位点显示在忙/等证据/空闲（只读）  
5. 有硬门禁时顶栏 **待办 · n** → 拉开抽屉 → 按 G1 拍板  

空办公室文案（改）：`还没有目标。建一个，同事才会开工。`（不再暗示「安静=只有 Inbox」）

## 补丁 · 填充板 vs 派工台（Harness调研 2026-09-19）

**边界一句：** 填充板只投影「目标被谁填到哪、产物在哪」（可读进度；协调者/Bot 自路由开跑）。派工台是人拖拽/指派/点「开跑」来决定谁做什么——后者是监工台，官方已拒（Grok Bot 砍 assignment board），**P0 禁止**。

**验收反例（防回灌）：**
- 槽位出现「指派给 / 拖到工位 / 开始跑」→ 已变派工台 → 打回
- 工位心跳可写回 owner 或前置 dispatch → 已变派工台 → 打回
- 填充槽只有「谁在填 / 填到哪 / 产物入口 / 等证据」→ 仍是填充板 → 过
